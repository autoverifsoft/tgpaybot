# Бот-витрина с оплатой через CryptoBot

Минимальный бот: несколько кнопок с товарами, оплата криптой, автоматическая
выдача сразу после платежа. Уведомление о продаже приходит вам в личку.

Разворачивается **бесплатно и без банковской карты**. Работает 24/7.

Ни баланса, ни корзины здесь нет намеренно: клиент нажимает кнопку и платит
сразу за товар — так меньше кода и меньше того, что может сломаться.

---

## Шаг 1. Настроить товары

Откройте **`items.py`** — это единственный файл, который нужно править.
Каждая запись = одна кнопка. Меняйте названия, цены, описания и главное —
поле `payload`: именно этот текст клиент получит после оплаты (ключ, ссылка,
инструкция, контакт для записи).

Кнопок может быть сколько угодно: добавляйте или удаляйте блоки `Item(...)`.

---

## Шаг 2. Проверить у себя на компьютере

Нужен [Python 3.11+](https://www.python.org/downloads/) (на Windows при
установке — галочка **«Add Python to PATH»**).

```bash
python -m venv .venv
```
```bash
# Windows:
.venv\Scripts\activate
# Mac/Linux:
source .venv/bin/activate
```
```bash
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `ADMIN_IDS`,
`CRYPTOBOT_TOKEN`. Остальное можно оставить пустым.

```bash
python app.py
```

В логе появится `Режим: polling`. Идите в Telegram, нажмите Start у своего
бота — увидите кнопки. Нажмите «Оплатить» — придёт настоящий счёт CryptoBot.

Проверить приём денег, не тратя своих: в `.env` добавьте
`CRYPTOBOT_NETWORK=testnet` и создайте отдельное приложение в
[@CryptoTestnetBot](https://t.me/CryptoTestnetBot) — там монеты бесплатные.

Прогнать автотесты (Telegram и CryptoBot не нужны):

```bash
python test_bot.py
```

## Шаг 3. Бесплатная база данных (2 минуты)

База хранит один факт: какие счета уже оплачены и выданы. Без неё после
перезапуска бот может выдать товар повторно.

На Render файлы стираются при каждом перезапуске, поэтому берём внешнюю базу.
**Neon** бесплатен постоянно (не триал) и не требует карты.

1. [neon.com](https://neon.com) → регистрация через GitHub.
2. Create project → любое имя, регион ближе к Европе.
3. На странице проекта → **Connection string** → скопировать.
   Строка выглядит так:
   `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`
4. Сохраните её — вставим на следующем шаге.

Про `sslmode=require` в конце можно не думать: бот сам приведёт строку
к нужному драйверу виду.

## Шаг 4. Выложить код на GitHub

1. [github.com/new](https://github.com/new) → имя репозитория → **Private** →
   Create repository.
2. Загрузите файлы: на странице репозитория **Add file → Upload files**,
   перетащите всё содержимое папки (кроме `.venv` и `.env`) → Commit.

Файл `.env` загружать нельзя — в нём токены. Он и так исключён через
`.gitignore`, но при ручной загрузке проследите сами.

---

## Шаг 5. Запустить на Render (бесплатно)

1. [render.com](https://render.com) → Get Started → войти через GitHub.
2. **New → Web Service** → выберите свой репозиторий.
3. Заполните:
   - **Language**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python app.py`
   - **Instance Type**: **Free**
4. Разверните **Advanced → Add Environment Variable** и добавьте:

| Key | Value |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_IDS` | ваш числовой ID |
| `CRYPTOBOT_TOKEN` | токен приложения CryptoBot |
| `DATABASE_URL` | строка подключения Neon из шага 3 |
| `WEBHOOK_SECRET` | любая длинная случайная строка |
| `SHOP_NAME` | название магазина |
| `SUPPORT_USERNAME` | ваш username без `@` |

5. **Create Web Service** и подождите пару минут.

Адрес сервиса Render подставит сам — переменную `PUBLIC_URL` заполнять не
нужно, бот прочитает её из окружения Render автоматически.

### Последний штрих — вебхук CryptoBot

В логах Render найдите строку:

```
УКАЖИТЕ ЭТОТ АДРЕС В НАСТРОЙКАХ ПРИЛОЖЕНИЯ CRYPTOBOT: https://ваш-сервис.onrender.com/cryptobot
```

Скопируйте адрес → [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → ваше
приложение → **Webhooks** → вставить адрес и **включить**.

После этого товар выдаётся через 1–2 секунды после оплаты. Если вебхук не
настроить, всё равно будет работать — но с задержкой до минуты, через
фоновую сверку.

## Шаг 6. Не дать сервису засыпать

Бесплатный сервис Render засыпает после **15 минут** без запросов, а
просыпается около минуты. Клиент этого ждать не станет.

Лечится бесплатным пингом:

1. [uptimerobot.com](https://uptimerobot.com) → регистрация (карта не нужна).
2. **Add New Monitor**:
   - Type: **HTTP(s)**
   - URL: `https://ваш-сервис.onrender.com/healthz`
   - Monitoring interval: **5 минут**
3. Create Monitor.

Теперь сервис получает запрос каждые 5 минут и не спит. Бонусом UptimeRobot
пришлёт письмо, если бот упадёт.

Бесплатных часов Render — 750 в месяц, а в месяце максимум 744. Одного
круглосуточного сервиса это ровно хватает. Второй бесплатный сервис в том же
аккаунте уже вылезет за лимит.

---

## Проверка, что всё живо

- Откройте `https://ваш-сервис.onrender.com/healthz` — должно быть `{"status": "ok"}`
- Напишите боту `/start` — кнопки на месте
- Отправьте `/stats` (только с вашего аккаунта) — статистика и баланс CryptoBot
- Проведите тестовую покупку на минимальную сумму и убедитесь, что товар пришёл

---

## Почему товар не уйдёт дважды

Оплату подтверждают два независимых механизма: вебхук CryptoBot и фоновая
сверка раз в минуту. Оба могут сработать одновременно — например, если
вебхук пришёл в момент сверки.

Защита в `db.mark_paid()`: статус переводится в `paid` одним SQL-запросом
с условием `WHERE status = 'pending'`. Кто первый — тот и выдаёт; второй
получает ноль изменённых строк и молча выходит. Это проверено тестом
«одновременные вебхук и сверка».

## Ограничения бесплатного варианта

Честно, чтобы не было неожиданностей:

- **512 МБ RAM и 0.1 CPU.** Для витрины с кнопками — с запасом. Тысячи
  одновременных пользователей это не выдержит.
- **Render может перезапустить сервис в любой момент** — на бесплатном тарифе
  используются свободные мощности. Бот поднимется сам, но пара минут
  недоступности возможна. Заказы при этом не теряются: они в Neon, а сверка
  доведёт оплаты до выдачи.
- **Neon: 0.5 ГБ и 100 CU-часов в месяц.** Для таблицы заказов это годы
  работы. База «спит» при простое и просыпается за доли секунды.
- **Нет админки для товаров.** Чтобы поменять цены или тексты, правите
  `items.py` и делаете commit — Render задеплоит сам за минуту.
- **Нет оплаты картой.** Только крипта через CryptoBot. Карты и СБП требуют
  ИП или юрлица и договора с платёжным провайдером.

Когда упрётесь в бесплатный тариф — Render Starter стоит $7/мес и убирает
засыпание и перезапуски, код менять не нужно.
